# GitHub PR 기반 개발 및 ChatGPT 코드 검수 운영 규칙 (MANDATORY)

본 프로젝트(`Ryan-Doyeong/my-phu-quoc`)에서 모든 코드 수정, 기능 개발, 버그 수정, 문서 및 설정 작업 시 아래 14가지 운영 원칙을 영구적으로 준수합니다.

## 1. 브랜치 및 작업 시작 원칙
1. **`main` 브랜치 직접 개발 금지**: `main` 브랜치에서 직접 코드를 수정하거나 커밋하지 않는다.
2. **작업별 전용 브랜치 생성**: 모든 작업마다 성격에 맞는 접두사(`feat/`, `fix/`, `chore/`, `docs/` 등)를 사용한 새 브랜치를 생성하여 작업한다.
3. **최신 원격 상태 확인 및 로컬 변경 보존**: 작업 시작 전에 최신 원격 상태(`git fetch origin`, `git status` 등)를 확인하며, 기존 미커밋 변경 사항이 있는 경우 절대 임의로 삭제하거나 덮어쓰지 않고 안전하게 보존한다.

## 2. 수정 범위 및 안전성 원칙
4. **요청 범위 준수**: 사용자가 명시적으로 요청한 범위만 수정하며, 요청하지 않은 주변 코드나 파일을 임의로 리팩터링하거나 변경하지 않는다.
5. **기존 자산 및 구조 보존**: 기존 기능, 다국어 번역(i18n), SEO 메타데이터, 라우트/URL 구조, 데이터베이스 및 JSON 데이터 구조를 불필요하게 변경하지 않는다. (루트 `AGENTS.md`의 데이터 및 메뉴 표준 지침과 함께 준수)
6. **위험 작업 사전 승인 필수**: `git push --force`, `git reset --hard`, 파일 대량 삭제, 배포/인프라 설정 변경, 환경변수 및 비밀정보(Secret) 변경은 반드시 사용자의 사전 승인을 받기 전에는 수행하지 않는다.

## 3. 검증 및 결과 보고 원칙
7. **빌드·린트·테스트 실행**: 코드 수정 후 프로젝트에 구성된 `npm run lint`, `npm run build` 및 테스트 스크립트를 확인 가능한 범위에서 반드시 실행하여 검증한다.
8. **정직한 실패 보고**: 빌드, 린트, 테스트 중 하나라도 실패하면 실패 내용과 원인을 투명하게 보고하며, 절대 임의로 성공으로 표시하거나 숨기지 않는다.
9. **작업 결과 종합 보고**: 작업 완료 시 **변경 요약**, **수정된 파일 목록**, **테스트/검증 결과**, **잔여 위험 요소(리스크)**를 명확히 정리하여 보고한다.

## 4. Pull Request 및 ChatGPT 코드 검수 원칙
10. **작업 브랜치 커밋 및 PR 표준화**: 모든 변경 사항은 작업 브랜치에 커밋 및 푸시(`git push -u origin <브랜치명>`)한 뒤, GitHub Pull Request(PR)를 생성하는 것을 표준 방식으로 한다.
11. **PR 본문 한국어 작성 필수 항목**: Pull Request 본문에는 다음 항목을 한국어로 명확히 작성한다.
    - **목적 (Purpose)**
    - **변경 내용 (Changes)**
    - **테스트 결과 (Test Results)**
    - **영향 범위 (Impact Scope)**
    - **검토 필요 항목 (Review Points)**
12. **ChatGPT 코드 검수 연동 보고**: PR 생성 후 ChatGPT가 코드를 검수할 수 있도록 **PR 번호 및 PR URL**을 사용자에게 즉시 보고한다.
13. **검토 의견 처리 및 최종 결정권**: ChatGPT의 코드 검토 의견은 개선 제안 사항으로 처리하여 분석·보고하며, 수용 여부 및 최종 병합 여부는 사용자가 결정한다.
14. **운영 반영 및 배포 승인 필수**: 운영 `main` 브랜치로의 PR 병합(Merge) 및 실제 프로덕션 배포는 반드시 사용자의 명시적 승인을 받은 후에만 수행한다.
